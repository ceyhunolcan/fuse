### Pattern-mode compatibility and balance

`files` and `pattern` remain required; `pattern_mode` is the only new request field. Unsupported modes fail. Only structural mode reserves `$name` and the standalone `...` token. A structural Python pattern permits adjacent `$` plus an ASCII identifier despite `$` being invalid in ordinary Python source; a JavaScript `$name` token uses the same capture rule. Source files still use the unchanged A lexer. There is no literal escape within structural mode: use exact mode to search literal `$name` or `...` tokens. Exact mode and an omitted mode preserve all A output and validation.

Each ellipsis expansion must form a self-contained sequence with an empty delimiter stack initially and finally, correctly nested matching pairs throughout, and no semicolon token anywhere in the expansion. Literal delimiters outside the ellipsis do not supply its stack. String-token punctuation is opaque. For multiple ellipses, choose expansion lengths lexicographically from left to right, minimizing the first length that permits the entire remaining pattern to match, then the next. At least one non-hole/non-ellipsis literal token is required in structural mode. Captures appear only on structural matches with a hole or ellipsis, and are `{}` for ellipsis-only special patterns. Repeated capture names compare exact token spelling, including case. B1 adds no replacement or file-saving operation.
