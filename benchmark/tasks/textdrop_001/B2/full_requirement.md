Add a top-level `backend` selector, default `snapshot` retaining exactly A state and behavior, or `journal`. Both must support all A operations and identical result semantics. Journal state is `{version:1,backend:"journal",events:[{snapshot:A_state},...]}`. On mutation append a new snapshot while preserving the existing prefix exactly; reads/list/render/export do not append. Reopen the journal in a fresh process from returned JSON. Import replaces logical contents by appending when contents change. Export always returns portable A snapshot JSON that can be imported into either backend. Reject unknown backends, malformed journal entries or backend/state mismatches. This is a behavioral requirement for interchangeable stores; no prescribed class hierarchy. Identity and sessions remain outside scope.

### Initialization and no-op rules

Missing/null state initializes the selected backend: snapshot uses the A empty store; journal uses an empty events list and the A empty store as its logical contents. An explicitly empty journal is valid; each existing event has exactly `snapshot`, containing a complete valid A state. Only `backend:"journal"` accepts a journal envelope, and only snapshot accepts an A envelope. Reopening uses the final snapshot, or empty A state when there are no events.

Append exactly when an operation changes the logical JSON state. An update to the same values and an import of an equal logical snapshot do not append; changed imports append one snapshot. Equality ignores object-key order and serialization formatting, but preserves list order and field presence. Reads/list/render/export never append. Prefix preservation is equality of existing event JSON data and event order, not serialized bytes. Portable export contains only A state, so importing it into a journal never imports that source's event history. Results match A exactly.
