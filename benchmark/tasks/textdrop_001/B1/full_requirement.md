### Bootstrap, deletion and backup lifecycle

Register and login are unauthenticated bootstrap commands, even when accounts already exist; an optional top-level session is ignored for those two operations. Registration of additional users remains public in this local benchmark. All other operations require a valid token whenever the account set is nonempty. Login sessions have no clock-based expiry; logout, account deletion or replacement by imported state controls validity. Logout/delete_account commands have exactly `op`. Return `{"logged_out":true}` or `{"deleted_account":username}` respectively. Registration/login require exactly `op`, `username`, `password`.

Before first registration, retain the exact A store and anonymous outputs. First registration adds identity state and an `owner:null` field to existing anonymous notes. Identity state has the A keys plus `accounts` (username to implementation-defined JSON credential-verifier record) and `sessions` (nonempty opaque token to registered username); every note adds `owner`, either a registered username or null. Validate the implementation's credential format and references, but no particular hashing or class design is prescribed. The public owner field is returned by create/get/list/update. Identity keys persist after the last account is deleted. Delete that user's owned notes and tokens, retain anonymous notes and `next_id`; with no accounts left, anonymous operations resume and newly created notes have owner null. Anonymous notes never transfer ownership automatically on registration.

Export produces the entire current state, including identity information if present. Import/export are administrative whole-store backup operations, authenticated against the current state before execution when accounts exist. Import validates and replaces the entire state; it may restore either a valid A snapshot or an identity snapshot. Afterward the imported account/session set is authoritative: old tokens absent from it are invalid, and restored tokens resume validity. Importing an A snapshot removes identity state and resumes anonymous A behavior. These caller-owned backups are trusted, not a secure isolation boundary or a promise that one user cannot restore other users' data. B1 has no backend selector or journal envelope.
